# Установка и администрирование

Раздел растёт вместе с Простором. Сейчас здесь: первый запуск, почта и уведомления, настройки и возможности, задания, файлы, вход, пользователи, группы, роли и права, проекты, поля и наборы значений, типы связей, API-токены, восстановление доступа администратора и работа за обратным прокси.

## Первый запуск

1. Запустите сервер (`make dev` для разработки или `make run` — собранный файл). Сервер сам создаёт таблицы в базе.
2. Пока сервис не настроен, сервер при каждом запуске пишет в журнал строку вида:

   ```
   WARN Prostor is not set up yet: open it in a browser and enter the setup code 0XZE-4B1X-KMS6
   ```

3. Откройте Простор в браузере — откроется мастер настройки. Введите код установки (регистр, пробелы и дефисы не важны), имя и почту администратора, пароль (не меньше 8 символов), язык трекера, адрес, по которому сервис будут открывать, и часовой пояс по умолчанию.
4. После «Завершить настройку» вы войдёте как администратор. Мастер больше не открывается, код перестаёт действовать.

Код нужен, чтобы сервер, открытый в интернет до настройки, не мог настроить посторонний. Для автоматической установки код можно задать заранее переменной `PROSTOR_SETUP_CODE` (не короче 8 букв и цифр).

## Почта и уведомления

Без почты Простор работает: уведомления собираются в колокольчик. Но письма — приглашения, подтверждения адресов, сбросы пароля и уведомления об изменениях задач — не уходят. Почта состоит из транспорта (почтового сервера) и переключателя, который решает, уходят ли письма вообще.

**Транспорт.** Пока сервер не задан на экране почты, Простор берёт его из переменных окружения — их задаёт тот, кто запускает сервер:

```bash
PROSTOR_SMTP_URL=smtps://robot:пароль@mail.example.com:465   # или smtp://…:587 — с STARTTLS
PROSTOR_MAIL_FROM="Prostor <tracker@example.com>"
```

Затем откройте «Администрирование» → «Почта»: сервер, имя пользователя и пароль (если сервер требует их отдельно от адреса), отправитель и адрес для ответов. Сервер, имя и пароль — секреты: после сохранения они больше не показываются и хранятся зашифрованными. Чтобы экран мог сохранять их, серверу нужна переменная окружения `PROSTOR_SECRET_KEY` (32 байта в base64); без неё экран скажет об этом и откажется сохранять. Пустое поле сохранённое значение не меняет, отметка «Убрать сохранённое значение» — удаляет.

- `smtp://` переходит на шифрование (STARTTLS), если почтовый сервер его предлагает; `?tls=required` в конце адреса требует шифрования обязательно. `smtps://` шифрует с самого начала (обычно порт 465).
- Отправитель — настоящий ящик на вашем домене с настроенным SPF, чтобы письма не попадали в спам. Адрес для ответов пуст — ответы уходят отправителю.
- Ссылки в письмах ведут на адрес Простора из мастера настройки. Если его не задали, — на адрес, с которого действовал человек.
- `make dev` сам отправляет письма в Mailpit: они видны на <http://127.0.0.1:8025>.

**Проверка и переключатель.** «Отправить проверочное письмо» шлёт письмо на любой адрес через сохранённый транспорт; если почтовый сервер откажет, сообщение об ошибке будет возвращено пользователю. Пока переключатель «Почта включена» выключен, ни одно письмо не покидает инстанс — даже при работающем транспорте. Сохранение нового сервера само ставит переключатель в «выключено»: включайте почту после успешной проверки. Пока настройки не тронуты, транспорт из переменных окружения считается включённым.

**Что приходит людям.** С включённой почтой на адреса из профилей уходят приглашения, подтверждения адресов и сбросы пароля; уведомления об изменениях задач — тем, кто включил письма во вкладке «Уведомления» учётной записи (в каждом письме — почему оно пришло, и ссылка на настройки); и отчёт о каждом использовании команды восстановления администратора — встроенному администратору.

## Настройки

«Администрирование» → «Настройки» — как ведёт себя инстанс в целом. Три раздела, каждый со своим сохранением; менять их может только системный администратор.

- **«Сервер»**. Адрес инстанса — полный, с `http://` или `https://`: по нему собираются ссылки в письмах и приглашениях. Пустое поле — ссылки строятся из адреса самого запроса. Адрес с `http://` вызывает предупреждение: всё идёт по сети открытым текстом. Если сохранённый адрес отличается от того, по которому открыта страница, Простор предупреждает: письма будут вести не сюда. После смены адреса экран напоминает: письма и приглашения пойдут с нового адреса, а прежний продолжает работать, пока на него идёт трафик. «Наибольший размер загрузки» — в мегабайтах или гигабайтах, не выше потолка сервера (он показан под полем). «Сеанс заканчивается после» (10–720 минут) и «„Запомнить меня“ длится» (1–365 дней). «Главная страница» — что открывается после входа тем, кто не выбрал своё: задачи, проекты или доски.
- **«Локализация»**. Язык системы (English или Русский) — язык писем и служебных текстов; язык интерфейса остаётся выбором каждого человека. Часовой пояс — список с поиском и текущим смещением; он достаётся тем, кто не выбрал свой. Формат даты — четыре варианта с образцом: «по языку интерфейса» (по умолчанию), `31.12.2000, 23:59`, `31 дек. 2000, 23:59` и `2000-12-31 23:59`; выбранный формат показывают списки задач, лента изменений и карточки, а месяцы в нём пишутся на языке того, кто смотрит.
- **«О системе»** — текущая версия сервиса.

## Возможности

«Администрирование» → «Возможности» — функции, которые включают для выбранных групп. Возможность есть у человека, если он состоит хоть в одной группе её списка, включая встроенные; пустой список выключает возможность для всех — экран переспросит перед этим. Пока в Просторе одна такая возможность: «Настройка доступа» — кому можно менять, кто смотрит, использует и редактирует теги, сохранённые поиски и доски (по умолчанию — все). Раздел «Общие для всех» появится, когда у инстанса появятся переключатели на всех сразу.

## Задания

Длительные задачи сервера — удаление проекта, значения полей в задачах, письма, перерисовка текстов, удаление файлов, истечение загрузок, просмотр картинок — идут заданиями в фоне; они переживают перезапуск сервера. «Администрирование» → «Задания» показывает их свежими вперёд: вид задания и его цель, когда началось, кто запустил, состояние (в очереди, выполняется, завершено, ошибка, отменено) и ход работы; упавшее задание пишет, почему.

- Отметки состояний и свободный поиск сужают список; слово с минусом `-` впереди исключает («`письмо -проект`» — письма без удалений проектов).
- «Отменить» спрашивает подтверждения: задание в очереди не выполнится вовсе, выполняющееся остановится, где стоит, — сделанное останется сделанным.
- «Повторить» ставит в очередь новое задание с теми же данными; доступно для упавшего.
- Изменения видны после обновления списка; задание уведомляет того, кто его запустил (строка в колокольчике).

## Файлы

Загруженные файлы — вложения задач, фото профилей, логотипы проектов — Простор хранит в каталоге на диске, в базе только их описания.

```bash
PROSTOR_FILES_DIR=/srv/prostor/files        # по умолчанию data/files рядом с запуском
PROSTOR_UPLOAD_CEILING_BYTES=1073741824       # потолок размера одного файла, по умолчанию 1 ГБ
PROSTOR_GRAVATAR_URL=https://gravatar.com/avatar/   # пусто — выключить загрузку фото из Gravatar
```

- **Резервные копии** должны включать этот каталог вместе с базой: без него задачи останутся без файлов.
- **Несколько серверов**: всем нужен один и тот же каталог (общий диск).
- **Размер файла**: действует меньшее из двух — настройка «Наибольший размер загрузки» (по умолчанию 10 МБ; «Администрирование» → «Настройки» → «Сервер») и потолок `PROSTOR_UPLOAD_CEILING_BYTES`, который задаёт тот, кто разворачивает сервер. Если перед Простором стоит обратный прокси, его лимит на размер запроса должен быть не меньше.
- **Gravatar**: картинку скачивает сам сервер — один раз, когда человек нажимает «Взять из Gravatar»; браузеры к Gravatar не обращаются. Серверу нужен выход в интернет к gravatar.com; если его нет или он не нужен, задайте пустой `PROSTOR_GRAVATAR_URL`, и кнопка пропадёт.
- Загруженные, но не прикреплённые файлы удаляются через сутки. Удалённые вложения пока остаются на диске до появления корзины; файлы удалённых проектов и учётных записей удаляются сами.

## Вход и выход

- Входят по имени пользователя или почте и паролю; регистр не важен.
- «Запомнить меня на этом устройстве» — вход сохраняется на 30 дней, даже если браузер закрыть. Без отметки вход заканчивается через час без действий или при закрытии браузера. Оба срока — настройки сервера (`session_idle_minutes`, `remember_me_days`); экран для их изменения появится в разделе администрирования.
- «Выйти» в меню учётной записи завершает вход сразу во всех вкладках этого браузера.
- После смены пароля вход на других устройствах завершается; API-токены продолжают работать.
- После 10 неудачных попыток входа под одним логином с одного адреса попытки с этого адреса блокируются на 15 минут; после 50 неудачных попыток с одного адреса — все попытки с него.
- **Забыли пароль.** Если почта настроена, на странице входа есть ссылка «Забыли пароль?». Письмо со ссылкой приходит только на подтверждённый адрес, ссылка действует час и один раз; после смены пароля вход на остальных устройствах завершается. Страница отвечает одинаково для любого адреса, так что по ней нельзя узнать, у кого есть учётная запись.

## Пользователи

Раздел «Администрирование» → «Пользователи» (его видят те, кто может чем-то управлять: создавать или менять учётные записи, видеть системные настройки, группы или роли).

- **Создать учётную запись**: имя, имя пользователя, почта и пароль. Отметка «Попросить сменить пароль при первом входе» стоит по умолчанию: человек сначала задаст свой пароль, и знать его будет только он. Новая учётная запись получает только то, что дают группы «Все» и «Все участники» (по умолчанию — видеть других людей и менять свой профиль); роли и группы назначаются на её странице.
- **Пригласить** (нужна почта): адреса через пробел, запятую или с новой строки. Учётные записи создаются сразу — доступ можно настроить заранее, — а человек получает письмо, задаёт пароль и при желании поправляет имя и имя пользователя. Ссылка действует 14 дней; на странице человека есть «Отправить приглашение ещё раз».
- **Отключить**: человек сразу теряет доступ — вход, сеансы и API-токены. Всё, что он сделал, остаётся. Можно указать причину и пометку («Приостановлена», «Больше не в организации» и т. п. — пометка ни на что не влияет). «Включить» возвращает доступ.
- **Удалить** — необратимо. Сначала показывается, что пропадёт (сеансы, токены, членство в группах, роли), и нужно выбрать замену: её адрес займёт старый идентификатор, а всё, что удалённый человек создал, останется подписанным как «Удалённый пользователь». Имя пользователя освобождается.
- **Попросить сменить пароль** (меню действий на странице человека): при следующем входе — а уже открытые сеансы сразу — человек сначала задаст новый пароль.
- Нельзя отключить или удалить себя и нельзя оставить Простор без системного администратора — такие действия отклоняются.
- **Кого видно без справочника.** Роль «Просмотр справочника» (по умолчанию — у всех участников) даёт видеть других людей и их почту. У кого её нет, видит остальных под номерами: «Пользователь 123456» — вместо имён в авторах, исполнителях, упоминаниях и списках; номер для каждой пары людей свой и не меняется. Почта, роли и группы чужого профиля открываются отдельным правом подробностей.

## Группы

«Администрирование» → «Группы». Группа — набор людей с общими ролями.

- Две группы есть всегда: «Все» (все учётные записи, включая гостя) и «Все участники» (все, кроме гостя). Состав у них автоматический, переименовать и удалить их нельзя. «Все участники» по умолчанию имеют роль «Просмотр справочника»: каждый видит других людей и их почту и меняет свой профиль.
- У группы есть название, описание и «автоматически добавлять новых»: каждая новая учётная запись сразу попадает в неё.
- Добавить человека в группу может только тот, у кого уже есть все права, которые даёт группа (исключение — «Изменение системных настроек»). Если прав не хватает, Простор называет, каких именно.
- При удалении группы выбирается замена: всё, что было доступно только удалённой группе, станет доступно группе-замене, а не всем. Замена занимает и её места: в командах проектов, в списках исполнителей, в видимости по умолчанию.
- Команды проектов тоже группы. Фильтр над списком показывает группы, команды или всё вместе; команда открывает страницу «Люди» своего проекта — меняется она только там.

## Роли и права

«Администрирование» → «Роли». Права выдаются только в составе ролей, роли — людям или группам.

- Шесть ролей встроены и не меняются: «Системный администратор», «Администратор проекта», «Участник проекта», «Просмотр справочника», «Создатель проектов», «Создатель учётных записей».
- Свою роль создаёт системный администратор: название, описание, права. Право сохраняется сразу при отметке; вместе с ним включаются права, без которых оно не работает, а при снятии — снимаются зависящие от него. Отметка «только глобально» означает, что право действует, только если роль выдана на весь Простор.
- В роль нельзя добавить право, которого нет у вас самих, и нельзя выдать роль, дающую больше ваших прав.
- Роль выдаётся на странице человека или группы («Выдать роль»): на весь Простор (только системный администратор) или в выбранных проектах (тот, кто настраивает эти проекты). Роль в проекте даёт только свои проектные права — например, «Системный администратор», выданный в проекте, не делает человека администратором Простора.
- На странице человека видно каждую его роль и откуда она: выдана лично или через группу.
- Удаление своей роли сначала показывает, у кого она есть, и отзывает её у всех.
- **Права автора.** Кто создал задачу, тот всегда может её читать и править её публичные поля — даже без права читать чужие задачи в проекте; свои комментарии и файлы автор тоже всегда видит. Удаление — отдельное право. Из этого собирают роль «податель видит только свои задачи».
- Изменения прав и системных настроек доходят до открытых вкладок сами, перезагружать страницу не нужно.

## Проекты

Раздел «Проекты» в главном меню. Проект видят только те, у кого в нём есть роль (лично, через группу или через команду проекта); для остальных его нет. Создавать проекты могут обладатели роли «Создатель проектов» и системные администраторы.

- **Создать проект** — выберите шаблон и назовите проект:
  - «Пустой» — поля, отмеченные «добавлять в новые проекты» (приоритет, тип, состояние, исполнитель и другие из стандартного набора);
  - «Скрам» — типы «Эпик», «Пользовательская история», «Задача», «Ошибка», свои состояния, поле «Спринты», «Стори-поинты», «Идеальные дни» и оценка;
  - «Канбан» — этапы от «Бэклога» до «Готово» и признак «Готовность» («Можно брать» / «Заблокирована»).
  Проекты «Скрам» и «Канбан» сразу получают свою доску с бэклогом.
- **Ключ** — короткий код проекта в номерах задач (`WEB-42`): латинские буквы, цифры и `_`, начинается с буквы, от 2 до 10 знаков. Мастер предлагает ключ по названию и сразу говорит, если такое название или ключ уже заняты. Там же можно задать номер первой задачи (по умолчанию 1); номера никогда не повторяются.
- Создатель становится **владельцем** и администратором проекта и входит в его **команду**.
- **Избранное** — звёздочка у проекта в списке и в шапке проекта: избранные проекты стоят в списке первыми.
- **Настройки** проекта (видят те, кто может его настраивать — по умолчанию администраторы проекта):
  - «Общие» — название, ключ, описание и видимость по умолчанию для новых задач и статей (группа или команда). После смены ключа старые номера задач и ссылки продолжают работать: старый ключ остаётся за проектом, и другой проект его не займёт.
  - «Люди» — владелец, команда и роли (ниже).
  - «Поля» — поля проекта (раздел «Поля и наборы значений»).
- **Архив**: проект становится доступен только для чтения и пропадает из выбора проектов и поиска; «Восстановить» возвращает всё как было.
- **Удалить** — необратимо: нужно ввести название проекта. Удаление идёт в фоне; проект сразу пропадает у всех, а у тех, кто может удалять, виден в разделе «Удаляемые проекты» с состоянием. Если удаление не удалось, его можно запустить ещё раз.

### Люди и команда

Настройки проекта → «Люди».

- **Команда** — люди и группы, которые работают в проекте. Группа в команде приводит всех своих участников, в том числе будущих. У команды есть **роли команды** (по умолчанию «Участник проекта»): их получает каждый, кто в команде, и только в этом проекте.
- Добавить в команду может тот, у кого есть все права, которые дают роли команды; если прав не хватает, Простор называет, каких именно. Удалить из команды можно человека, добавленного лично, или группу целиком; человек, пришедший через группу, уходит вместе с группой. Роли, выданные лично, при этом остаются.
- **Роли вне команды** — можно выдать роль в проекте человеку или группе, не добавляя их в команду (например, наблюдателям).
- Ниже показаны роли, выданные на весь Простор (например, системные администраторы): они меняются на странице человека или группы.
- **Передать владение**: новый владелец получает роль администратора проекта; роли прежнего владельца остаются.
- Исполнителем задачи можно выбрать любого из команды: в список исполнителей проекта входит сама команда.

## Поля и наборы значений

Поле — то, что есть у каждой задачи: приоритет, состояние, исполнитель, срок, версия. Поле заводится в Просторе один раз и добавляется в проекты; в каждом проекте у него свои настройки. Значения полей-списков хранятся в **наборах значений**, которые проекты могут делить между собой или иметь свои.

- **Стандартные поля** создаются при настройке Простора на выбранном языке: «Приоритет», «Тип», «Состояние», «Исполнитель», «Компонент», «Исправлено в версиях», «Затронутые версии», «Исправлено в сборке», «Срок», «Оценка», «Затрачено». Все, кроме «Срока», добавляются в новые пустые проекты. Это обычные поля: их можно переименовать и настроить.
- **Типы полей**: строка, текст, целое и дробное число, дата, дата и время, длительность (вводится как `1н 2д 3ч 30м` или `1w 2d 3h 30m`: неделя — 5 рабочих дней по 8 часов), список значений, состояние (у значения есть отметка «решённое»), пользователь, группа, версия (выпущена, даты начала и выпуска), сборка (дата сборки), значение с ответственным (например, компоненты). Списки, пользователи, группы, версии, сборки и значения с ответственным могут хранить несколько значений.
- «Администрирование» → **«Поля»**: все поля Простора, их порядок по умолчанию, отметка «добавлять в новые проекты» и настройки, с которых поле начинает в новом проекте. Название и синонимы поля общие для всех проектов: их меняет системный администратор или тот, кто настраивает все проекты с этим полем. На странице поля — проекты, которые его используют, и доски, где оно работает колонками, дорожками, цветом карточек или оценкой. Удаление поля убирает его из всех проектов вместе со значениями в задачах; перед удалением Простор показывает, сколько проектов, задач и досок это затронет. Доска с удалённым полем продолжит открываться и подскажет своим редакторам, что поправить. Значения стираются в фоне, но из задач пропадают сразу.
- «Администрирование» → **«Наборы значений»**: все наборы, сколько проектов и полей их используют.
- Настройки проекта → **«Поля»**: поля проекта в его порядке (перетаскиванием или «Переместить выше» / «Переместить ниже» в меню строки), «Добавить поле» — существующее или новое. У поля в проекте: может ли оно быть пустым, подпись пустого значения («Не назначена», «Без срока»), значения по умолчанию для новых задач, скрытое ли оно (скрытые поля видят только те, у кого есть право на скрытые поля). Поле, которое не может быть пустым и не имеет значения по умолчанию, обязательно при создании задачи.
- **Общий набор** меняется сразу во всех проектах, которые его используют, поэтому менять его может только тот, кто настраивает их все. Остальным Простор предлагает «Сделать копию для проекта»: у проекта появится свой набор с теми же значениями.
- Значения можно переименовывать, раскрашивать (12 цветов; название значения видно всегда), упорядочивать, архивировать (архивное значение не предлагается при выборе, но остаётся в задачах) и удалять.
- **Удаление значения**, которое стоит в задачах: Простор показывает, в скольких задачах оно стоит, и предлагает выбрать другое значение того же набора на замену или оставить поле пустым. Замена проходит в фоне, а в истории каждой задачи появляется запись от вашего имени (без уведомлений).
- **Убрать поле из проекта**: значения этого поля в задачах проекта стираются сразу; если добавить поле обратно, они не вернутся. Перед этим показывается, сколько задач их потеряет.
- **Отметка «решённое»** у значения состояния: если её поменять, задачи с этим значением в фоне станут решёнными или снова открытыми. Задача решена, когда все поля-состояния её проекта стоят в решённых значениях; момент решения запоминается (и сбрасывается, когда задачу открыли повторно) — его ищут в запросах условием «решена:».
- **Сделать копию набора для проекта**: задачи проекта переходят на значения копии сразу.

## Типы связей

Задачи можно связывать между собой: «блокирует», «подзадача для», «дубликат». Вид связи — это **тип связи**. У типа есть внутреннее название (его видят администраторы) и названия сторон: как связь читается со стороны первой задачи («родитель для») и со стороны второй («подзадача для»). Названия сторон люди видят в задачах; позже они станут словами поиска и команд.

- **Стандартные типы** создаются при настройке Простора на выбранном языке: «Связь» (без направления: «связана с» с обеих сторон), «Зависимость» («блокирует» / «заблокирована»), «Дубликат» («имеет дубликат» / «дубликат») и «Подзадача» («родитель для» / «подзадача для»). «Дубликат» и «Подзадача» встроенные: на них опираются подзадачи и счётчики, поэтому их нельзя изменить или удалить (на странице они отмечены замком). «Связь» и «Зависимость» — обычные типы.
- **Направление**: «Без направления» — одно название для обеих сторон; «Направленная» — два названия; «Иерархия» — два названия, и у каждой задачи может быть только один «родитель» этого типа, а цепочка не может замкнуться на себя (так устроены подзадачи).
- «Администрирование» → **«Типы связей»**: все типы, их стороны, направление и сколько связей каждого типа есть. Создавать, менять и удалять типы может системный администратор; тот, у кого есть только право просмотра настроек, видит страницу без кнопок.
- Названия: до 50 символов, одной строкой, без `<`, `>`, `/` и `:`. Внутренние названия не повторяются, названия сторон не повторяются ни у каких двух типов (без учёта регистра).
- **Переименование** действует сразу на все связи этого типа, в том числе в истории задач.
- **Смена направления**: при переходе к «без направления» второе название пропадает; при возврате к направленному нужно задать его снова, и задачи получат свои стороны как прежде. В «иерархию» тип можно перевести, только если у его связей ни у одной задачи нет двух «родителей» и нет замкнутых цепочек.
- **Удаление** переносит тип в корзину: перед удалением Простор показывает, сколько связей это скроет. Связи удалённого типа не видны нигде, пока тип не восстановят кнопкой «Восстановить» в разделе удалённых типов на той же странице. Восстановить нельзя, если за это время его название занял другой тип — сначала переименуйте один из них.

## API-токены

Токены нужны скриптам и другим программам. Создаются на странице учётной записи: название и доступ к двум областям — «Трекер» (проекты, задачи, доски, отчёты) и «Администрирование» (пользователи, группы, роли, настройки), для каждой «Чтение» или «Чтение и изменение». У токена никогда не больше прав, чем у его владельца.

Значение токена показывается один раз — скопируйте его сразу. Программа передаёт его в заголовке:

```bash
curl -H "Authorization: Bearer tfp_…" https://tracker.example.com/api/v1/users/me
```

Срока действия у токена нет; чтобы отозвать токен, удалите его — он перестанет работать сразу. Токеном нельзя сменить пароль, создать или удалить токены: это делается только во входе через браузер.

Вызвать API со страницы другого сайта (из браузера) можно, только если администратор внёс адрес этого сайта в «Настройки» → «Сервер» → «Источники API» — по одному источнику в строке, например `https://app.example.com`. Токен такая страница передаёт сама, как скрипт; вход по cookie между сайтами не работает никогда, какие бы источники ни были разрешены. Пустой список (по умолчанию) значит: только страницы самого сервера.

## Восстановление доступа администратора

Если никто не может войти как администратор, на сервере (там, где запущен Простор, с той же переменной `DATABASE_URL`) выполните:

```bash
prostor recover-admin                      # администратор, созданный мастером настройки
prostor recover-admin anna@example.com     # любой пользователь по имени или почте
prostor recover-admin --new ops ops@example.com "Ops Team"   # новый администратор
```

Команда выдаёт новый одноразовый пароль (печатает его один раз), включает учётную запись, делает её системным администратором и завершает её входы. Войдите с этим паролем и сразу смените его на странице учётной записи. Каждое использование записывается в журнал аудита; если почта экземпляра включена, отчёт об использовании приходит письмом на адрес встроенного администратора.

## За обратным прокси

Если Простор стоит за nginx, Caddy или балансировщиком, перечислите их адреса в `PROSTOR_TRUSTED_PROXIES` (через запятую, можно диапазонами: `127.0.0.1, 10.0.0.0/8`). Тогда сервер берёт адрес посетителя из заголовка `X-Forwarded-For` — без этого все попытки входа выглядят пришедшими с адреса прокси, и ограничение неудачных попыток срабатывает для всех сразу.

Если адрес Простора начинается с `https://`, cookie входа отправляется только по HTTPS.

Прокси не отменяет правила API: со страниц других сайтов `/api/v1` отвечает только источникам из «Настройки» → «Сервер» → «Источники API»; страницы самого сервера работают без списка.
